\begin{abstract}
Photorealistic 3D digital twins remain difficult to query because visual
observations, objects, and spatial evidence grow faster than the context
available to a reasoning agent. We study a representation-agnostic hierarchy
that prunes a scene before semantic grounding. The system supports
deterministic lexical and embedding controls, an instruction-tuned language
agent, an original Cursor-Agent/MCP construction path, and a hierarchy
constructed directly from posed RGB-D observations. On five indoor/outdoor
captures (97 RGB-D views; 150 queries), a complete Qwen2.5 run checks
\AgentViews{} views per query and obtains hit@1 / hit@3 of \AgentHitOne{} /
\AgentHitThree{} on 125 verified positives while recording every prompt, call,
native token count, latency, and trace. Five direct Cursor MCP calls construct
scene partitions without access to manual zones and reach pairwise F1
\CursorPairwiseFOne{} against the overlapping manual reference. A separate
CLIP constructor reads zero manual ViewJSON records and reaches pairwise F1
\RawPairwiseFOne{} from RGB, depth, and poses. In the deterministic control,
mean per-query view reduction is \ViewSavingsPerQuery{}\%, while the hit@1
difference is inconclusive and hit@3 declines significantly under a paired
bootstrap. ScanNet relation-aware graph search reaches Acc@0.25 0.604 versus
0.500 without relations while checking 90.3\% fewer objects than flat search.
Replica is reported only as an oracle-map sanity ceiling.
\keywords{Digital twins \and 3D scene graphs \and RGB-D \and Language agents
\and Grounding.}
\end{abstract}

\section{Introduction}
Digital twins based on neural rendering and 3D Gaussian Splatting
(3DGS)~\cite{kerbl20233dgs} support immersive inspection, but appearance alone
does not answer questions such as ``where can I sit near reception?'' or
``which view shows the stage screen?'' A practical interface must ground
language in scene evidence while controlling how much of a large map reaches
the semantic reasoner.

Flat retrieval is a strong baseline: it exposes every record to one scorer and
avoids pruning mistakes. Its cost, however, grows linearly with the map. Scene
graphs and language fields provide rich semantics~\cite{kerr2023lerf,
langsplat2024,gu2023conceptgraphs,bbq2024}, yet two questions remain important
for digital twins: (i) can a hierarchy reduce records and tokens without
silently changing the scorer, and (ii) can the hierarchy itself be obtained
from raw capture data rather than hand-authored semantic records?

We answer both questions with a reproducible prototype. It separates
construction cost from per-query cost and separates automatic predictions from
manual evaluation references. The same 150-query benchmark is executed by
deterministic controls, a local instruction-tuned language agent, and a frozen
vision-language model (VLM). All agent prompts, model calls, exact tokenizer
counts, response tokens, latencies, branch decisions, and ranked views are
saved. The original agent architecture is evaluated independently: Cursor
invokes the hierarchy-construction MCP tool once per scene and semantically
partitions its geometric candidates without seeing manual zones. A stricter
automatic constructor consumes only RGB images, depth maps, and camera poses;
the manual hierarchy is opened only after the automatic artifact is written.

\paragraph{Contributions.}
\begin{itemize}
\item A typed, traceable hierarchy for top-down semantic search over shared
3D-scene records, with lexical, embedding, and instruction-agent scorers.
\item A complete 150-query instruction-agent evaluation with native token and
call accounting, rather than a stub-only demonstration.
\item A measured Cursor-Agent/MCP construction path with pose and
pose-plus-semantic controls, plus a raw RGB-D-to-hierarchy pipeline using
frozen CLIP, depth statistics, poses, and predicted branch labels. Both are
evaluated against but not constructed from manual zone references.
\item Same-input controls on five captures, BBQ-aligned Replica/ScanNet
object-grounding pilots, and native ConceptGraphs/LangSplat feasibility runs,
with protocol differences stated explicitly.
\end{itemize}

\section{Related Work}
\paragraph{Language-aligned 3D representations.}
LERF~\cite{kerr2023lerf}, LangSplat~\cite{langsplat2024}, Semantic
Gaussians~\cite{semanticgaussians2024}, and LEGS~\cite{legs2024} attach
language or semantic features to neural fields and Gaussian primitives.
ConceptFusion~\cite{conceptfusion2023} and OpenScene~\cite{openscene2023}
construct open-vocabulary 3D representations. Our contribution is orthogonal:
we control the records presented at query time and can operate over a manual
index, an oracle object map, or a predicted map.

\paragraph{Scene graphs and hierarchical reasoning.}
ConceptGraphs~\cite{gu2023conceptgraphs}, HOV-SG~\cite{hovsg2024}, and
Hydra~\cite{hydra2022} organize entities and relations for mapping and
planning. BBQ~\cite{bbq2024} is the closest object-grounding reference: it
combines a 3D object graph with deductive language reasoning and reports
Acc@$k$ on Replica and ScanNet. SayPlan~\cite{rana2023sayplan} grounds an LLM
in a hierarchical 3D scene graph for scalable planning, while
Search3D~\cite{takmaz2025search3d} studies hierarchical open-vocabulary 3D
segmentation. We focus on controlled branch pruning, complete accounting, and
the manual-versus-automatic hierarchy gap.

\paragraph{Grounding and context control.}
ScanRefer~\cite{scanrefer2020} established language grounding in RGB-D scans,
and OpenLex3D~\cite{openlex3d2025} advocates tiered evaluation for
open-vocabulary 3D representations. Context-pruning work in language systems
similarly separates relevance selection from generation~\cite{
promptcompression2024,attentionrag2025,provence2025}. Our evaluation therefore
reports retrieval quality and efficiency jointly; fewer records alone do not
establish a better method.

\section{Method}
\subsection{Hierarchical scene records}
\label{sec:hierarchy}
Let a scene hierarchy be $H=(V,E)$ with root $v_0$. Each node is
\begin{equation}
v_i=(\mathrm{id}_i,\tau_i,A_i,x_i,R_i,B_i,I_i).
\end{equation}
It stores a type $\tau_i$, its
ancestor path $A_i$, searchable content $x_i$, spatial relations $R_i$,
optional 2D/3D boxes $B_i$, and supporting observations $I_i$. Branch nodes
represent zones or regions; entity nodes represent objects, landmarks, signs,
or facilities; evidence nodes point to RGB-D views. Containment edges and
typed spatial relations remain separate.

\begin{figure}[t]
\centering
\includegraphics[width=0.88\linewidth]{figures/fig_tree_traversal.pdf}
\caption{Top-down query execution. A root-to-branch decision produces a
candidate subset; the same leaf scorer used by flat search ranks the retained
views or objects. Every visited node and retained ID is written to the trace.}
\label{fig:tree}
\end{figure}

This representation supports a controlled comparison. Flat search scores all
eligible leaves. Hierarchical search first selects branches and then applies
the identical leaf scorer. If $N$ is the full leaf set and $N_q$ the retained
set, flat scoring is $O(N)$ and branch-pruned leaf scoring is $O(N_q)$ after a
small top-level gate. An explicit fallback may restore the full set; it is
recorded rather than hidden.

\subsection{Agent/MCP hierarchy construction}
\label{sec:mcpconstruction}
The semantic-record construction track implements the original two-pass
agent architecture. Given camera translations $p_i$, the MCP server first
builds an adaptive proximity graph. Its edge threshold is
\begin{equation}
t=3.5\,\operatorname{median}_i\min_{j\ne i}\lVert p_i-p_j\rVert_2 ,
\end{equation}
and connected components form conservative geometric candidates. A
deterministic semantic control merges components only when their view
summaries contain either a complementary facing pair or a shared room type
and landmark.

For the agent variant, Cursor calls
\texttt{build\_spatial\_clusters} once for each scene with geometry assistance
enabled, then partitions and labels the returned candidates from the saved
room, facing, landmark, and object summaries. It cannot read the manual-zone
reference, call the tree persistence tool, or modify scene data. All five
decisions and rationales are frozen before evaluation. Cursor's UI exposes
neither provider tokens nor a stable wall-clock field, so both are reported
as unavailable rather than inferred. This construction experiment is separate
from the query-side Qwen benchmark: Cursor measures MCP orchestration, while
the pinned local model provides reproducible query metrics and exact tokens.

\subsection{Deterministic and embedding controls}
The lexical control normalizes case, stop words, aliases, and plurals. A branch
score is token overlap between the query and concatenated branch content.
Branches with at least half the maximum positive overlap are retained; if all
branch scores are zero, every branch remains eligible. Leaves are ranked by
overlap, normalized overlap, node-type priority, and stable ID. The flat
variant applies the same ranking to every leaf.

The semantic control replaces overlap with BGE-small-en-v1.5 cosine
similarity. Query, branch, and leaf text use the model's native tokenizer.
Both controls are deterministic and credential-independent; they establish
whether gains come from hierarchy or from a changed scorer.

\subsection{Instruction-agent traversal}
\label{sec:agent}
We execute Qwen2.5-0.5B-Instruct~\cite{qwen25report} locally in deterministic
CPU inference. For a
query $q$ and candidate $c$, the agent receives:
\begin{quote}\small\ttfamily\raggedright
Judge scene-query relevance using semantic meaning and affordances.
Answer exactly Yes or No.\par
Query: <q>. Candidate: <c>. Relevant? Answer exactly Yes or No.
\end{quote}
At the first phase, candidates are top-level branches. The two branches with
largest normalized next-token probability $p(\texttt{Yes}\mid q,c)$ are
retained. The second phase applies the same instruction to their view records
and returns the top three. Candidate prompts are batched within a phase, but a
phase remains one recorded model invocation. Generation is greedy and emits
exactly one decision token per candidate.

Each query trace stores the system message, every rendered chat prompt,
candidate-to-alias mapping, \texttt{Yes}/\texttt{No} probabilities, generated
decisions, ranked IDs, branch IDs, native input/output tokens, model calls, and
wall-clock latency. This is an actual instruction-model execution; it is not a
lexical stub or an unverified provider cache.

\subsection{Automatic raw RGB-D hierarchy}
\label{sec:automatic}
The automatic constructor has a strict source boundary: it may read
\path{transforms.json}, RGB images, and depth arrays, but not ViewJSON,
manual zone files, or the checked-in tree. For each view $i$, it computes a
frozen CLIP image embedding $f_i$, camera translation $p_i$, and depth
descriptor $d_i$ containing valid-depth ratio and five quantiles. Standardized
features are concatenated as follows. We use the ViT-B/32 CLIP
checkpoint~\cite{radford2021clip}.
\begin{equation}
 z_i=[f_i;\;0.5\,p_i;\;0.2\,d_i].
\end{equation}
Deterministic farthest-point initialization and k-means cluster the views.
The number of clusters maximizes silhouette score over
$k=2,\ldots,\min(8,\lfloor n/3\rfloor)$. A fixed scene-agnostic vocabulary of
20 place categories is encoded with the same CLIP model; each cluster receives
the category whose text embedding has highest cosine similarity to its mean
image embedding.

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/fig_agent_mcp_workflow.pdf}
\caption{Two complementary construction tracks feed the same query pipeline.
Cursor semantically partitions MCP proximity clusters built from scene
records; the raw track bypasses ViewJSON and predicts branches from RGB-D and
poses. Manual zones are opened only for evaluation after artifacts are frozen.}
\label{fig:workflow}
\end{figure}

The raw hierarchy is serialized before the evaluator opens manual zone
references. Structural agreement is measured by pairwise precision, recall,
F1, and Rand index over co-clustered view pairs. For query evaluation, one
CLIP text embedding ranks (i) all images, (ii) images in the two best manual
branches, or (iii) images in the two best automatic branches. Thus all three
variants share the image/text scorer.

\subsection{Object grounding and spatial relations}
For public object maps, a parsed query produces a target, optional relation,
and optional anchor. Exact labels, lexical overlap, type, and deterministic
affordance expansions form the base object score. Relations such as
\emph{near}, left/right, above/below, and front/behind use stored links or box
centers. A satisfied relation adds $0.35$, a resolved violation subtracts
$0.35\times0.35$, and unresolved geometry contributes zero. A fallback expands
the universe when confidence is below $0.45$, geometry is invalid, or a
required relation remains unresolved. Exact source object IDs and boxes are
preserved for Recall@1 and 3D IoU.

\subsection{Accounting}
Construction and query costs are never combined. Construction reports source
files, model invocations, text tokens, images processed, and latency. Each
query reports checked views/objects/nodes, serialized context, native or
explicitly estimated tokens, calls, and latency. Provider tokens are not
inferred. Local tokenizer counts are exact for the associated model; legacy
character-divided-by-four values are labeled estimates.

\section{Datasets and Evaluation}
\subsection{Internal captures}
The internal benchmark contains five manually captured indoor/outdoor scenes:
Conference Hall, Museum, Theater, outdoor street, and outdoor drone. It has 97
posed RGB-D views, 97 manual ViewJSON records, 1,066 semantic items, and 150
queries. Of these, 125 positive queries have verified expected view IDs and 25
negative queries are excluded from hit@$k$ because they lack independent
negative GT. Query types include simple objects, attributes, affordances,
relations, and multi-hop descriptions.

\subsection{Public datasets and external executions}
The public track follows the BBQ scene subset where available. Replica uses
room0--2 and office0--4 (8 scenes, 575 official boxes, 56 queries including 8
negatives). ScanNet uses scenes 0011\_00, 0030\_00, 0046\_00, 0086\_00,
0222\_00, 0378\_00, 0389\_00, and 0435\_00 (392 official boxes). The core
ScanNet track has 48 mapped Nr3D/Sr3D+ queries; an extended track has 64
queries, including 8 negative and 8 additional positive cases.

These object-grounding pilots search oracle semantic candidates and therefore
measure retrieval over official IDs and boxes, not automatic semantic-map
perception. Native ConceptGraphs builds predicted object maps from sampled
RGB-D; native LangSplat learns a language field. Their protocols differ and
they are reported as execution references, not a ranking.

\subsection{Metrics}
Efficiency uses mean checked views/objects, input tokens, model calls, and
latency. View retrieval uses hit@1, hit@3, and mean reciprocal rank (MRR) on
the 125 positive internal queries. Object grounding uses exact-ID Recall@$k$,
MRR, 3D IoU, and Acc@$\tau$. Negative accuracy is reported only where verified
negative labels exist. Structural hierarchy quality uses pairwise F1 and Rand
index. Missing predictions stay in the relevant denominator with score zero.

\subsection{Deterministic same-input controls}
On the manual records, flat lexical checks 19.4 views and 3,168 estimated
tokens per query. Hierarchical lexical checks 4.77 views and 1,014 tokens.
Mean per-query reductions are \ViewSavingsPerQuery{}\% (95\% CI
[\ViewSavingsLow{}, \ViewSavingsHigh{}]) and \TokenSavingsPerQuery{}\%
([\TokenSavingsLow{}, \TokenSavingsHigh{}]), respectively. The ratio of the
displayed mean view counts is separately $1-4.77/19.40=75.4\%$; it differs
slightly because the primary estimate averages each query's reduction before
rounding.

On the 125 positive queries, hit@1 is 0.680 versus 0.768 flat. Its paired
graph-minus-flat difference is \HitOneDelta{} with 95\% CI
[\HitOneLow{}, \HitOneHigh{}], which includes zero and is therefore
inconclusive. Hit@3 is 0.808 versus 0.928; its difference is
\HitThreeDelta{} [\HitThreeLow{}, \HitThreeHigh{}], a significant decline
under the paired 10,000-resample percentile bootstrap. BGE graph search checks
3.90 views and 1,567 native tokens, with hit@1 0.664 and hit@3 0.784; flat BGE
obtains 0.680 and 0.928. These controls show that aggressive pruning saves
context but can remove relevant evidence.

\subsection{Replica and ScanNet object grounding}
Table~\ref{tab:public} updates the earlier pilots with the calibrated v3
relation-aware scorer. Replica remains an oracle-map ceiling: graph and flat
reach exact-ID Recall@1 and Acc@0.25 of 1.0 on 48 positives, and negative

On the 48-query ScanNet core, graph and flat both reach exact-ID Recall@1 /
Acc@0.25 of 0.604. Graph Recall@3 is 0.812 and MRR is 0.718 while checking 4.73
objects and 219 estimated tokens, versus 49.0 objects and 2,117 tokens flat.

was unresolved. The v3 scorer uses confidence, geometry-validity, and margin
gates and abstains from a relation adjustment when those checks fail.

\section{Discussion and Limitations}
Three findings emerge. First, hierarchy is an effective cost-control mechanism:
all graph variants inspect fewer views or objects. Second, retrieval quality
depends on both branch construction and branch scoring. The manual lexical and
BGE controls lose hit@$k$, the Cursor/MCP experiment shows that the intended
agent construction path is executable, and the raw hierarchy quantifies the
additional cost of predicting branches without semantic records. Third, a real
instruction model can execute the traversal with complete accounting, but the
small CPU model should be viewed as a reproducible agent baseline rather than
a state-of-the-art reasoning result.

The five captures and manual labels are small and not independent public GT.
The automatic constructor predicts coarse view clusters rather than
object-instance segmentation. CLIP labels come from a fixed generic
vocabulary. Public oracle-map results isolate retrieval and cannot establish
semantic perception accuracy. Native ConceptGraphs and LangSplat runs are
diagnostic because compute, frame sampling, geometry, and output types differ.
Segmentation mIoU remains unavailable without paired per-point predictions.
Finally, no fair official BBQ execution is included, so we make no superiority
claim.

\section{Reproducibility}
The release contains the 150-query list, exact expected-view labels, per-query
results, raw traces, construction artifacts, CSV summaries, run
configurations, model revisions, and validation reports. The instruction run

\section{Conclusion}
We presented a traceable hierarchy for semantic search over 3D scene records
and evaluated both the querying agent and the origin of the hierarchy. A
complete instruction-tuned language model traverses all 150 queries with
prompts, calls, tokens, latency, and quality saved. A separate raw RGB-D
constructor builds and labels branches without manual ViewJSON, then exposes
its structural and retrieval gap relative to the manual hierarchy. The
original Cursor-Agent/MCP path is also measured through frozen construction
decisions rather than conflated with Qwen's query metrics. Together with
same-input controls, calibrated ScanNet/Replica pilots, and native external
executions, these results turn hierarchy from an assumed component into a
measured part of the digital-twin search pipeline.
