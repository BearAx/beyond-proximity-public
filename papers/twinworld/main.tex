\begin{abstract}
Built-environment digital twins based on 3D Gaussian Splatting (3DGS) are photorealistic but lack an explicit semantic layer for natural-language querying. We present SemanticSplat, a graph-pruned semantic search layer that organizes captured views into a hierarchical zone--region--object tree and answers queries via top-down traversal instead of exhaustive flat search over the same semantic items. On five manually captured indoor/outdoor digital-twin pilot scenes (96 views; 150 queries), graph traversal cuts average views checked from $19.4$ to $4.77$ ($75.5\%$) and input tokens from $3168$ to $1014$ ($68.2\%$). Under stub lexical matching with verified view labels ($n{=}125$), hit@1 is $0.68$ (graph) vs.\ $0.768$ (flat), so the internal track shows a quality--cost tradeoff rather than free quality preservation. We further align evaluation with BBQ-style object grounding on official Replica and ScanNet pilot subsets: on a 48-query ScanNet language pilot, graph search matches flat lexical Recall@1 / Acc@0.25 ($0.271$) while checking about $77\%$ fewer objects. We position the work as hierarchical context pruning for queryable 3DGS twins, not as a claim of superiority over BBQ, whose official code is not reproduced here.
\keywords{Digital twins \and 3D Gaussian Splatting \and Scene graphs \and Semantic search \and 3D object grounding.}
\end{abstract}

\section{Introduction}
Digital twins of the built environment increasingly rely on neural rendering,
including 3D Gaussian Splatting~\cite{kerbl20233dgs}, for interactive
visualization. TwinWorld applications include facility queries, robotics
hand-off, and semantic mapping. They need more than geometry and appearance: a
user should ask ``where can I sit near the reception?'' and receive a grounded
viewpoint or object. Exhaustive flat search over all views or objects is simple
but wastes context and scales poorly with scene size.

Language-field methods~\cite{kerr2023lerf,langsplat2024} distill features into the field but do not expose hierarchical pruning. Object-centric scene graphs such as ConceptGraphs~\cite{gu2023conceptgraphs} and BBQ~\cite{bbq2024} provide strong public-dataset object grounding; BBQ in particular reports Acc@$k$ on Replica/ScanNet and Sr3D+/Nr3D/ScanRefer. Our focus is complementary: a hierarchical semantic index over 3DGS-captured views with measured \emph{query-time} context pruning, evaluated under a same-input graph-vs-flat protocol and aligned with BBQ-style Acc@$k$ / Recall@1 on public-dataset pilots.

\paragraph{Contributions.}
\begin{itemize}
\item A rendering-first semantic-map layer for queryable 3DGS digital twins with hierarchical traversal and affordance expansion.
\item Same-input graph-vs-flat evidence on five captured scenes and BBQ-aligned object-grounding pilots on official Replica (8 scenes) and ScanNet (8 scenes).
\item Honest baseline status: internal flat lexical / embedding variants, ConceptGraphs full captured-scene run, LangSplat smoke, BBQ as related-work metric guide (official BBQ code not run).
\end{itemize}

\section{Related Work}
\paragraph{Language fields and 3DGS semantics.}
LERF~\cite{kerr2023lerf}, LangSplat~\cite{langsplat2024}, and related Gaussian semantics embed language for open-vocabulary pointing. They optimize a different native representation than tree traversal over shared semantic items.

\paragraph{Object-centric and hierarchical scene graphs.}
ConceptGraphs~\cite{gu2023conceptgraphs}, BBQ~\cite{bbq2024}, HOV-SG~\cite{hovsg2024}, and Hydra~\cite{hydra2022} construct graphs for grounding, navigation, or robotics. BBQ is the closest public-dataset grounding reference: object IDs, captions, 3D extents, spatial relations, and deductive LLM reasoning over a compact subgraph~\cite{bbq2024}. We cite BBQ Acc@$k$ tables as literature context, not as measurements from this repository.

\paragraph{Positioning.}
SemanticSplat targets hierarchical context control for 3DGS digital twins. Measured comparisons are same-input graph vs.\ flat lexical/embedding on identical scenes, items, queries, and labels. We do not claim superiority over BBQ without a same-protocol official-code run.

\section{Method}
\subsection{Capture and semantic index}
Users capture posed RGB(-D) views from a 3DGS or RGB-D scene and annotate or convert structured view records (objects, landmarks, room cues, short summaries). These records form the shared search units for both graph and flat methods (Fig.~\ref{fig:system}).

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/fig_system_overview.pdf}
\caption{SemanticSplat pipeline: capture $\rightarrow$ semantic index $\rightarrow$ hierarchy $\rightarrow$ query-time pruning. Graph and flat consume the same items.}
\label{fig:system}
\end{figure}

\subsection{Hierarchical tree and traversal}
Items are organized as zones $\rightarrow$ regions $\rightarrow$ object/view leaves. Queries are decomposed into constraints; the tree is traversed top-down and irrelevant branches are pruned before leaf confirmation (Fig.~\ref{fig:tree}). The flat baseline scans the same items exhaustively.

\begin{figure}[t]
\centering
\includegraphics[width=0.92\linewidth]{figures/fig_tree_traversal.pdf}
\caption{Schematic top-down traversal for a room-scoped screen query: solid path kept, dashed branches pruned.}
\label{fig:tree}
\end{figure}

\subsection{Object grounding output}
For BBQ-aligned evaluation, each query records selected object/view/node IDs, predicted 3D bbox when available, traversal path, checked objects/views/nodes, runtime, and estimated tokens. Construction cost is reported separately from query-time cost.

\subsection{Search variants}
We evaluate graph, graph+calibrated fallback, flat lexical, and flat embedding on the same public-dataset pilots, plus ablations (no hierarchy, no relation rerank, no fallback).

\section{Experiments}
\subsection{Internal five-scene graph vs.\ flat}
Across 150 queries, graph traversal reduces average views checked from $19.4$ to $4.77$ ($75.5\%$) and input tokens from $3168$ to $1014$ ($68.2\%$). Cumulative tokens are $475$k flat vs.\ $152$k graph (Fig.~\ref{fig:cumulative}). On $125$ GT queries with verified \texttt{expected\_view\_ids}, stub-lexical hit@1 is $0.68$ (graph) vs.\ $0.768$ (flat) and hit@3 is $0.808$ vs.\ $0.928$ (Fig.~\ref{fig:five-scene}). Thus hierarchy buys large context savings with a hit@$k$ tradeoff under the current stub matcher---not a free win on retrieval quality.

\subsection{Public-dataset BBQ-aligned pilots}
Table~\ref{tab:public} summarizes frozen Person~2 runs. On Replica, graph and flat lexical reach a Recall@1 / Acc@$k$ ceiling of $1.0$ on oracle candidates---a protocol sanity check, \emph{not} independent perception accuracy. \subsection{Baselines status}
ConceptGraphs has a full five captured-scene run, but no Replica/ScanNet run.
LangSplat has official sofa smoke only. BBQ official code is \textbf{not run};
its paper tables are related-work evidence only~\cite{bbq2024}.

\section{Limitations}
\begin{itemize}
\item Manual five-scene annotations are reference labels, not independent public GT.
\item Internal stub-lexical hit@$k$ currently favors flat over graph (hit@1 $0.68$ vs.\ $0.768$); public pilots match quality while cutting objects checked.
\item Public pilots use oracle semantic candidates; Replica Acc@$k{=}1.0$ is a ceiling sanity result.
\item mAcc/mIoU/fmIoU are unavailable without predicted segmentation arrays.
\item Relation reranking currently underperforms its ablation on ScanNet pilot.
\item No same-protocol BBQ official-code comparison; no superiority claim.
\item Stub / deterministic lexical matching is not live provider-backed VLM evaluation.
\end{itemize}

\section{Reproducibility}
The supplementary artifact freezes run IDs, commit provenance, environment
notes, data-license notes, one command per experiment, aggregate and per-query
metrics, and figure-generation scripts. An automated 33-check gate verifies the
paper values against the frozen JSON. Numbers in this PDF therefore follow the
saved machine-readable results rather than superseded notes.

\section{Conclusion}
SemanticSplat shows that hierarchical graph pruning reduces query-time context for 3DGS digital twins under a controlled same-input protocol. On the internal five-scene track the savings are large ($75.5\%$ views / $68.2\%$ tokens) with a stub-lexical hit@$k$ tradeoff; on BBQ-aligned ScanNet/Replica pilots, Acc@$k$ matches flat lexical while checked objects drop sharply. We do not claim BBQ superiority. Future work: stronger relation-aware search, predicted segmentation track, and fair same-protocol BBQ execution if permitted.
