\begin{abstract}
3D Gaussian Splatting (3DGS) provides photorealistic rendering but weak semantic structure for natural-language environment queries. We present SemanticSplat, a rendering-first pipeline that builds a hierarchical semantic index from captured views and answers queries via top-down graph traversal instead of exhaustive flat search over the same semantic items. On five manually captured indoor and outdoor scenes (96 views, 1,046 semantic items) and a legacy Conference Hall demo scene, we compare graph-pruned lexical search against a flat lexical baseline under a documented same-input protocol. Across 150 benchmark queries, graph traversal reduces average views checked by 71.4\% and input tokens by 65.1\% relative to flat search, while hit@1 on 125 queries with verified view labels is 0.792 (graph) vs.\ 0.768 (flat). We report limitations honestly: manual reference labels rather than independent ground truth, stub lexical matching rather than live provider-backed VLM evaluation, and no metric 3D localization benchmark.
\end{abstract}

\section{Introduction}
3DGS~\cite{kerbl20233dgs} enables real-time novel view synthesis, but the representation itself does not encode room structure, affordances, or object-level semantics needed for queries such as ``find a place where I can sit'' or ``where is the screen in the conference room?'' Existing semantic 3D approaches either distill language features into radiance fields~\cite{kerr2023lerf}, which struggle with compositional reasoning, or build explicit 3D object graphs from segmentation~\cite{gu2023conceptgraphs}, which can be fragile for open-vocabulary hierarchy construction.

SemanticSplat takes a rendering-first approach: capture posed RGB views from a 3DGS scene, annotate them with structured ViewJSON records, organize them into a hierarchical semantic tree, and answer queries by traversing that tree top-down. A flat baseline scans the same semantic items exhaustively. Our research question is whether graph pruning reduces search cost without sacrificing useful retrieval quality when both methods operate on identical inputs.

\paragraph{Contributions.}
\begin{itemize}
    \item A prototype semantic-map layer above captured 3DGS views with MCP-backed infrastructure and Query Flow logging.
    \item A same-input graph-vs-flat benchmark over five captured scenes plus a legacy demo scene, measuring views checked, tokens, and GT-aware hit@k where verified labels exist.
    \item An affordance expansion layer for intent-style queries (e.g.\ sit, exit, charge phone).
    \item Honest reporting of scope: manual reference labels, stub evaluation mode, and baseline smokes without superiority claims.
\end{itemize}

\section{Related Work}
\paragraph{Language fields and 3DGS semantics.}
LERF~\cite{kerr2023lerf} and related methods embed vision-language features into radiance fields or Gaussians for open-vocabulary pointing, but typically lack explicit hierarchical structure for context control.

\paragraph{Open-vocabulary 3D scene graphs.}
ConceptGraphs~\cite{gu2023conceptgraphs}, OpenScene, and BBQ build explicit graphs from lifted 2D detections or point clouds. These methods target object graphs and relational reasoning; our work instead evaluates whether a manually curated hierarchical semantic index can reduce traversal cost for environment-understanding queries.

\paragraph{Hierarchical scene graphs.}
Robotics-oriented systems such as Hydra construct multi-level spatial graphs with stronger geometric priors. SemanticSplat uses a lighter-weight tree built from captured views and manual or VLM-assisted ViewJSON annotations.

\paragraph{Positioning.}
We do not claim superiority over ConceptGraphs or LangSplat. Repository evidence includes one-frame ConceptGraphs smoke and official LangSplat sofa smoke only; fair same-scene comparison remains future work. See \texttt{docs/baselines/related\_work\_article\_matrix.md} for the full matrix.

\section{Method}

\subsection{Capture and semantic index}
Users navigate a 3DGS \texttt{.ply} scene in the browser, capture views (RGB, depth, pose), and produce ViewJSON records listing objects, landmarks, room cues, and summaries. Five captured scenes contain 96 annotated views and 1,046 semantic items. Trees are stored per scene under \texttt{backend/data/scenes/<scene\_id>/tree/}.

\subsection{Hierarchical tree and query traversal}
Queries are decomposed into structured constraints, then the semantic tree is traversed top-down. Irrelevant zones and regions are pruned before leaf-level confirmation. The flat baseline scans the same semantic items without hierarchy.

\subsection{Affordance-aware expansion}
Intent queries map to affordance categories (e.g.\ \textit{sittable} $\rightarrow$ chair, sofa, bench) before candidate ranking. This is implemented as a deterministic expansion layer (\texttt{backend/query/affordance.py}).

\subsection{Evaluation protocol}
Graph and flat methods share scenes, semantic items, query strings, and benchmark labels. Efficiency metrics include views checked, input tokens, context size, and infrastructure elapsed time. Quality metrics (hit@1, hit@3) are computed only for queries with verified \texttt{expected\_view\_ids}. Manual ViewJSON labels are reference labels, not independent ground truth.

\subsection{Legacy demo scene (\texttt{default})}
On the Conference Hall demo scene (19 views, hierarchical tree with 15 nodes), an earlier benchmark reports larger token reductions (8.5$\times$) and estimated latency speedups (4.1$\times$) under a documented timing model. This scene motivated room-disambiguation failure analysis: flat search can return a screen in the wrong room while graph traversal reaches the ballroom stage screen.

\subsection{Baselines and scope boundaries}
ConceptGraphs and LangSplat smoke tests confirm adapter feasibility but do not provide five-scene accuracy or efficiency comparison. Live and cached-live provider evaluation are out of scope for this sprint. ScanNet evaluation is postponed.

\section{Limitations}
\begin{itemize}
    \item \textbf{Manual reference labels:} Expected objects and views are verified from ViewJSON, not independent annotators.
    \item \textbf{Stub evaluation mode:} Reported five-scene runs use lexical stub matching, not live VLM API calls.
    \item \textbf{No metric 3D localization:} Predicted and ground-truth 3D boxes are unavailable; 3D IoU is not reported.
    \item \textbf{Uneven graph benefit:} Some queries still require many graph view checks; savings vary by query type and tree shape.
    \item \textbf{Baseline comparison:} External baselines are literature context plus minimal smokes, not head-to-head same-input benchmarks.
\end{itemize}

\section{Conclusion}
SemanticSplat shows that hierarchical graph pruning can reduce semantic search cost over captured 3DGS scenes when graph and flat methods share the same semantic index. On five scenes and 150 queries, graph traversal cuts views checked and tokens substantially while maintaining comparable hit@1 on verified view labels. Future work includes live VLM evaluation, richer zone-region-object graphs, independent GT, and fair external baseline comparison.
