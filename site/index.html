Research question

Can hierarchy reduce query context without changing the semantic map?

The method organizes the same records used by flat search into scene, zone, object, and view-evidence levels. A query retains likely branches, ranks their leaves, and expands only when confidence or geometry requires fallback.

Safest current claim

Hierarchy substantially reduces checked views and serialized query context. A complete local instruction-agent run and an automatic RGB-D constructor establish reproducible execution, while the measured quality gaps define the next research target rather than a superiority claim.

Method

Two construction tracks, one query protocol

The current system can construct a hierarchy through Cursor Agent and MCP over geometric clusters, or predict one directly from RGB, depth, and camera poses. Both feed the same traceable retrieval pipeline.

01

Read scene evidence

Consume manual scene records or posed RGB images, depth arrays, and camera metadata.

02

Construct branches

Use reference zones, pose clustering, Cursor-MCP decisions, or frozen CLIP predictions.

03

Route the query

Score branches with the lexical control, BGE embeddings, or a traced instruction model.

04

Return evidence

Rank stable view or object IDs and save branch decisions, cost, latency, and quality fields.

Five captured scenes, 150 queries

Graph reduces mean views by 75.5% and estimated context tokens by 68.2%. On 125 queries with verified view labels, hit@1 is 0.680 graph versus 0.768 flat; hit@3 is 0.808 versus 0.928.

Inspect the frozen metrics JSON

Complete model-backed controls

The BGE graph checks 3.90 views/query with hit@1 0.664 and hit@3 0.784. Qwen2.5-0.5B-Instruct completes all 150 queries with 300 calls and 239,893 exact native tokens, reaching hit@1 0.368 and hit@3 0.696.

The Qwen run is a reproducible CPU stress-test baseline. It underperforms lexical retrieval and is not presented as a state-of-the-art reasoning result.

BGE metricsQwen metrics

Hierarchy without manual ViewJSON

A frozen CLIP ViT-B/32 constructor consumes all 97 RGB images, depth arrays, and poses with zero manual ViewJSON or zone reads. It reaches macro pairwise F1 0.487 and checks 10.0 views/query, versus 19.4 for flat CLIP.

Cursor Agent also invokes the MCP construction tool once per scene. Its 18-zone hierarchy reaches pairwise F1 0.616 and checks 5.53 views/query.

Limits

What this release does not claim

  • The five internal semantic indexes are manual reference annotations, not independent GT.
  • ScanNet and Replica pilots use oracle semantic candidates; they do not measure semantic-perception accuracy.
  • ConceptGraphs and LangSplat use different map-construction and evaluation protocols, so their metrics are not a fair leaderboard.
  • Lexical context is a deterministic text-size estimate. BGE, CLIP, and Qwen counts use their pinned native tokenizers.
  • Qwen2.5-0.5B is a complete but weak CPU baseline; a 7-8B instruction-model run remains important for a main-track submission.
  • The current graph search saves context but trails flat lexical hit@k on the internal verified-view track.
